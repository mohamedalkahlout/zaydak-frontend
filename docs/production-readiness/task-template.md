# قالب المهمة ودليل إغلاق المرحلة

هذا القالب للأعمال القادمة. لا تستبدل خطوات المرحلة بوصف عام، ولا تسجل نجاحًا قبل تنفيذه. معرفات المهام على شكل `P05-T03`، والبنود التاريخية على شكل `R-001` في سجل التغطية.

## قالب مهمة

```markdown
### Pxx-Txx — عنوان يصف النتيجة المطلوبة

| الحقل | القيمة |
|---|---|
| الحالة | لم تبدأ |
| المالك / المراجع | أسماء فعلية |
| الأولوية | حاجب إطلاق / عالية / تحسين مؤجل بقرار |
| المصدر | R-xxx أو B-xx أو بند TODO أو نتيجة اختبار |
| الاعتماد | مهمة/قرار يجب أن يسبقها |
| النسخة والبيئة | commit + إعداد بيئة غير سري |

#### الهدف

السلوك الذي يجب أن يحصل عليه العميل/التاجر/المشغّل.

#### المشكلة

السلوك الحالي، كيف نعيد إنتاجه، أثره، وروابط الملفات.
تصنيف الدليل: قراءة كود / اختبار منفّذ / تقرير قديم / تحقق خارجي مطلوب.

#### الحل

سبب اختيار الحل، وحدوده، والطبقات التي تتغير.
اذكر حماية الصلاحيات والبيانات والتوافق إذا تأثرت.

#### خطوات التنفيذ

- [ ] إثبات المشكلة أو تسجيل أنها أُصلحت سابقًا مع دليل.
- [ ] تنفيذ الإصلاح/إعداد المزوّد/قرار التشغيل المحدد.
- [ ] تنفيذ اختبار مناسب للمخاطرة؛ حالة نجاح وفشل وحالات تزامن أو إعادة محاولة إن لزمت.
- [ ] تحديث وثائق السلوك ومرجع API إذا تغيرا.
- [ ] تسجيل النتيجة والتراجع والمتابعة.

#### شروط القبول

- [ ] سلوك قابل للقياس، بنتيجة متوقعة محددة.
- [ ] أثر البيانات/المبالغ/الصلاحيات صحيح بعد الفشل وإعادة المحاولة.

#### دليل التحقق

| التاريخ | النسخة | البيئة | الأمر/السيناريو | المتوقع | الفعلي | رابط الدليل |
|---|---|---|---|---|---|---|
| — | — | — | — | — | لم ينفذ | — |

#### التراجع

متى نوقف؟ كيف نرجع؟ هل نحتاج تعويضًا ماليًا أو إجراء بيانات بدل إعادة نسخة كود؟

#### المتبقي

إن كانت محجوبة: السبب والمالك وما يفتحها. إن كانت مكتملة: رابط المراجعة.
```

## قالب إغلاق مرحلة

```markdown
### إغلاق Pxx

- النسخة المختبرة:
- البيئة:
- المهام المكتملة:
- شروط القبول ودليل كل شرط:
- نتائج الاختبارات: ناجح / فاشل / متخطى، مع أسباب التخطي:
- بنود التقرير التي غُطيت:
- القدرات المستبعدة بقرار وروابط اختبار تعطيلها:
- المخاطر المتبقية ومالكها وموعدها:
- دليل تجربة التراجع/الاستعادة المناسبة:
- المراجع وتاريخ الإغلاق:
```

## قواعد الأدلة

- احفظ التقارير واللقطات في مكان وصول مناسب واربطها هنا؛ لا تلصق مفاتيح أو cookies أو رموز تحقق أو بيانات عملاء.
- قراءة الكود لا تثبت إعداد الحساب الحي. لقطة لوحة مزوّد لا تثبت الرحلة كاملة. اختبار API لا يغني عن اختبار المتصفح حين يكون العيب في التنقل أو الجلسة.
- إغلاق مرحلة لا يغلق بنودًا غير مرتبطة بها. عند تغير كود مؤثر لاحقًا تُعاد فحوصه قبل إصدار P11.
- القدرات المصنفة «جاهزة» في التقرير القديم تحتاج أدلة مناسبة للإصدار، مع اختبار تراجعي حسب المخاطرة؛ لا نعيد كتابة اختبارات شكلية لكل ملف لمجرد رفع العدد.
