## الهدف

تحويل التكاملات المختارة للإطلاق إلى مسارات يمكن تشغيلها ومراقبتها وإيقافها بأمان، مع تكلفة صحيحة لكل متجر ولكل مزوّد.
المرحلة تصلح القدرات الموجودة ضمن نطاق P00؛ إضافة قناة أو مزوّد جديد تحتاج قرار نطاق مستقل ولا تدخل تلقائياً في تجهيز الإنتاج.
هذا ملف خطة، ولا يثبت تشغيل مزوّد أو نجاح اختبار أو معالجة ثغرة.

## الحل المعتمد

1. سجل قدرات للإطلاق: `مفعّل ومتحقق` أو `معطّل`؛ الواجهة والـAPI والعامل الخلفي تقرأ القرار نفسه.
2. لكل عملية خارجية معرّف ثابت، حالة محفوظة، مهلة، سياسة إعادة محاولة، وأثر قابل للمصالحة مع المزوّد.
3. فصل حصّة التاجر عن تكلفة المنصة: ردّ حصّة عملية فاشلة لا يعني أن المزوّد لم يحتسب تكلفة.
4. تثبيت المتجر والمستخدم والصلاحيات في الخادم لكل قناة وأداة؛ النموذج لا يختار هوية التنفيذ.
5. حجز ذري قبل الإنفاق ثم تسوية مرة واحدة، مع تسجيل الكلفة الفعلية أو التقديرية أو المجهولة بوضوح.
6. إجراء مدمر أو تعديل واسع ينتظر موافقة إنسان على الحمولة المحددة؛ رمز يستطيع النموذج استدعاءه وحده ليس موافقة إنسان.

## النطاق وما يؤجّل

- ضمن النطاق: OTO، تخزين Bunny، Resend أو ناقل البريد المعتمد، SMS، WhatsApp، Telegram، الاستيراد، webhooks، AI الموجود والمفعّل.
- قناة اختيارية لا تنجح تُعطّل بقرار نطاق موثّق، بما يشمل الوصول المباشر للـAPI والمهام المجدولة والـfallback إلى متغيرات البيئة.
- قناة تحقق تعتمد عليها رحلة الدخول المختارة لا يجوز تأجيلها دون توفير رحلة دخول مدعومة ومختبرة.
- تؤجّل موصلات سلة/زد الجديدة، قنوات جديدة، وفيديو أو أدوات AI جديدة؛ لا تُعرض كقدرات جاهزة أو مدفوعة.
- قواعد الأموال وقرار refund في P05/P06؛ هذه المرحلة تثبت تسليم الحدث إلى المزوّد وإعادة المحاولة والمصالحة فقط.

## مهام التنفيذ بالترتيب

- [ ] **P08-T01 — تثبيت القائمة.** اكتب لكل تكامل مالكه، استخدامه، حساب بيئة الاختبار، تكلفة تشغيل تجربة، وحدود التفعيل وخطة الإيقاف؛ لا تسجّل المفاتيح.
- [ ] **P08-T02 — فحص الإعداد الفعلي.** اختبر resolved provider بعد سلسلة قاعدة البيانات والبيئة، وحالة `off`، وفشل المفتاح؛ اربط التسجيل والمراقبة بمخرجات P03/P04.
- [ ] **P08-T03 — الشحن.** نفّذ عرض السعر، إنشاء شحنة، طباعة الملصق، الإلغاء والتتبع على بيئة المزوّد؛ أعد طلب الإنشاء بعد timeout وأثبت عدم إنشاء شحنتين.
- [ ] **P08-T04 — الملفات.** أثبت upload/download/delete على Bunny وصلاحية النطاق وMIME والحدود؛ افحص روابط الصور المستوردة والفشل الجزئي ومنع جلب الشبكات الخاصة وفق P01.
- [ ] **P08-T05 — البريد وSMS.** أثبت وصول OTP واستعادة الحساب وتأكيد الطلب إلى جهات اختبار مملوكة؛ تحقق من هوية المرسل والـadapter المثبت وسلوك timeout وإعادة المحاولة.
- [ ] **P08-T06 — حالة التسليم.** احفظ محاولة كل قناة ونتيجتها ومعرّف المزوّد؛ لا تعد إرسال قناة نجحت بسبب فشل قناة ثانية؛ صِل bounce/complaint وحظر الإرسال بقرار P07.
- [ ] **P08-T07 — WhatsApp وTelegram.** اختبر الربط والفصل وإعادة الاتصال والتذكرة وقراءة الرسائل؛ راجع عقد GraphQL لصندوق الوارد مقابل schema، ثم اختبر SSE فعلياً.
- [ ] **P08-T08 — قرار WhatsApp.** وثّق ناقل Evolution الحالي والقيود التشغيلية المثبتة مع مالك المنتج؛ لا تصف القناة بأنها تكامل Meta معتمد؛ أصلح القناة أو عطّلها ضمن نطاق الإطلاق.
- [ ] **P08-T09 — webhooks.** افحص توقيع/سر كل قناة، منع replay، المخطط والحجم، الأحداث الخارجة عن الترتيب، ومطابقة المتجر؛ خزّن الحدث قبل تأكيد الاستلام وفق عقد المزوّد.
- [ ] **P08-T10 — استعادة الوظائف.** اختبر crash بعد الإرسال وقبل حفظ النتيجة، retries وbackoff، الصف الميت، وإعادة التشغيل اليدوي المصرح؛ لا تعاود عملية مالية مجهولة النتيجة دون مصالحة P06.
- [ ] **P08-T11 — الاستيراد.** أثبت PRODUCT مقابل STORE على مصدري Shopify وWooCommerce مصرح بهما؛ افحص العملة وrobots وحدود الزحف والهوية الموحدة للمصدر وحدود الصور والبيانات.
- [ ] **P08-T12 — استيراد قابل للاستعادة.** اختبر preview واعتماد دفعة فشلت في المنتصف ثم استئنافها دون تكرار؛ احفظ التقرير وأرصدة المزوّد والكلفة ولقطة التسعير حتى عند الإلغاء والفشل.
- [ ] **P08-T13 — مصفوفة AI.** احصر Vendor Agent وCustomer Bot وStorefront Assistant وStudio والمحرر والإثراء؛ اربط كل مسار بمزوّد ونموذج وحصّة وصلاحية وسياسة تسجيل بيانات. تتبع جميع مستهلكي خدمة Python المذكورة في التقرير: إثبات خدمة ومالك وعقد استجابة ونشر وhealth/timeout واختبار فشل، أو تعطيل جميع المستهلكين من الخادم والواجهة والعمال بقرار D06؛ عنوان URL في البيئة وحده لا يثبت وجود الخدمة.
- [~] **P08-T14 — حدود التنفيذ.** طبّق نواتج P02 على GraphQL وREST/SSE وchat workers؛ اختبر متجرين لنفس المالك، وأدوات الأسعار الجماعية، ورفض أي متجر قادم من نص النموذج.
- [ ] **P08-T15 — الموافقة والمحتوى.** اربط الموافقة بالفعل والموارد والمتجر والمستخدم والصلاحية ووقت الانتهاء؛ أبطل replay؛ اختبر حقن نص من تقييم/سؤال/استيراد؛ لا تختزل مستند المحرر الطويل إلى 600 حرف ثم تستبدله كاملاً.
- [ ] **P08-T16 — حصص ذرية.** اختبر الحجز والتسوية والتحرير تحت طلبات متزامنة، انتهاء نافذة الحصة، فشل Redis، crash، callback مكرر وإلغاء؛ لا تُستهلك حصتان لنفس صورة عبر Studio والوكيل.
- [ ] **P08-T17 — وحدة التكلفة.** اختر مع P06 وحدة دقيقة ثابتة، مثل micro-units صحيحة أو Decimal مضبوط؛ هاجِر السجلات والتجميعات؛ امنع تقريب كل نداء صغير إلى سنت وخفض الكلفة الصغيرة إلى صفر.
- [ ] **P08-T18 — الاستهلاك الحقيقي.** التقط input/output/cached tokens وكل خطوة وتلخيص وفشل قابل للفوترة؛ فضّل تكلفة المزوّد، وإلا استخدم snapshot تسعير مؤرّخاً؛ غياب البيانات ينتج `unknown` أو تقديراً معلّماً.
- [ ] **P08-T19 — منع تكرار القيود.** ضع مفتاحاً فريداً للعملية/المحاولة المستحقة؛ callback واحد يُحتسب مرة، ومحاولة جديدة فوّترها المزوّد تبقى كلفة مستقلة؛ صالِح usage مع فواتير/سجل المزوّد.
- [ ] **P08-T20 — خفض الإنفاق بقياس.** قارن السيناريوهات نفسها قبل/بعد تقليل الأدوات والسياق وحدود الخطوات؛ قِس cache hits وزمن الرد ودقة إتمام المهمة؛ اختبر مزوّداً فعلياً بميزانية تجربة معتمدة.
- [ ] **P08-T21 — الخطط واللوحات.** احسم المفاتيح غير المطبّقة أو المتداخلة في تدقيق AI؛ لا تَبِع حدوداً وهمية؛ اعرض كلفة وفشل واستعمال كل متجر/ميزة/مزوّد، مع تنبيهات وkill switch فعلي.
- [ ] **P08-T22 — تنبيهات توفر المخزون.** إذا بقيت ضمن D06، أثبت تحقق جهة الاتصال والاشتراك والإلغاء، وربط تغير المخزون بإرسال واحد لكل حدث واستحقاق؛ امنع تسريب قائمة المشتركين وفق P02، واختبر إعادة المحاولة دون إزعاج متكرر. وإلا عطّل الاشتراك والإدارة والعامل والوعود المتعلقة بها مع سياسة للطلبات السابقة.
- [ ] **P08-T23 — توثيق وتسليم.** حدّث feature/API docs وعقود webhooks وrunbooks وقرار النطاق؛ سلّم الأدلة إلى P09/P10 دون بيانات عملاء أو أسرار.

## ملاحظة لازمة حول تكلفة السياق

غياب `cache_control` في المستودع لا يثبت غياب caching عند المزوّد. توثيق Groq يذكر التخزين التلقائي للنماذج الداعمة، وأن الإصابة بالـcache ليست مضمونة: [مرجع Groq الرسمي](https://console.groq.com/docs/prompt-caching).
لذلك تقدير خفض التكلفة 90% والمدة المذكوران في التقرير فرضية تجارية تحتاج قياساً؛ لا يدخلان معيار القبول أو التسعير كوعد.
تُراجع النماذج والأسعار ووحدات الاستخدام بتاريخ التنفيذ؛ تاريخ مراجعة المرجع لهذه الخطة 2026-09-16.

| بريد نجح وTelegram فشل | إعادة محاولة القناة الفاشلة فقط، دون تكرار تأكيد الطلب |

| النموذج يحاول prepare ثم delete بنفسه | لا حذف حتى موافقة بشرية صحيحة؛ تغيير الحمولة يلغي الموافقة |
| SSE أو أداة جماعية في متجر A | لا قراءة أو كتابة في B حتى إذا كان المالك واحداً |

| نداء مدفوع فشل أو أُلغي بعد التنفيذ | تسوية حصّة العميل حسب السياسة، وبقاء تكلفة المزوّد في حساب المنصة |

| إيقاف تكامل لديه مفتاح في البيئة | لا إعادة تفعيل خفية؛ الواجهة والـAPI والعامل يعكسون الإيقاف |
| اشتراك مخزون ثم إلغاء أو إعادة حدث التوفر | لا إرسال بعد الإلغاء ولا تكرار لنفس الاستحقاق، وقائمة المستلمين محمية |

## معايير القبول

- [ ] جميع التكاملات المفعّلة نجحت على مسارها الفعلي بأدلة مؤرخة مرتبطة بـSHA.
- [ ] لا وصول عابر للمتاجر ولا كتابة AI مدمرة تتجاوز موافقة الإنسان أو صلاحياته.
- [ ] الحصص والميزانية والتسوية تمنع سباقات التزامن، وتتعامل مع replay والفشل وكلفة المحاولات.
- [ ] حقول الكلفة ووحداتها متوافقة؛ المجهول ظاهر؛ توجد مصالحة فعلية وتنبيه وإيقاف مجرّب.
- [ ] الاستيراد يلتزم بالنطاق المعلن ويحفظ التقدم والتكلفة عند الفشل، أو مغلق في الخادم والواجهة بقرار نطاق.
- [ ] البريد/الرسائل الضرورية للمصادقة والتجارة تعمل؛ كل قناة اختيارية غير متحققة مغلقة ومعلنة بصدق.
- [ ] تمت مراجعة P07 لبيانات المحادثات والمستلمين والاحتفاظ؛ توثيق الميزة والـAPI مطابق للتنفيذ.

## الاعتماديات والقرارات المفتوحة

- يُحسم في P00 أي القنوات والأسطح تبقى في الإصدار؛ لا يجيز هذا الملف تفعيل حسابات أو إرسال رسائل إلى عملاء حقيقيين.
- P06 ومالك التسعير يحسمان وحدات الكلفة وسياسة ردّ الحصة وتسعير مفاتيح AI؛ P07 يحسم استخدام البيانات والموافقة على التسويق.
- P03 يثبت مفاتيح التشغيل والطوابير وseed الخطط؛ P04 يثبت أن التنبيه يصل وأن محتواه منقّح.
- P02 يملك إصلاح العزل والصلاحيات؛ قبول هذه المرحلة يحتاج إعادة اختباره عبر القنوات الفعلية.

## الرجوع عند التعثر

أوقف المسار المتضرر عند حد الإنفاق/التسريب/التكرار، وأوقف المنتجين الجدد للوظائف قبل إعادة تشغيل المستهلكين.
احتفظ بسجل الأحداث والحجوزات ومعرّفات المزوّد للمصالحة؛ لا تمسح الطابور أو تعيد المال أو تخصم الحصص جماعياً.
أعد الإصدار السابق المتوافق مع البيانات وفق P03، وأبقِ التكامل مغلقاً إلى أن تثبت إعادة تجربة الحادثة؛ تغيير DNS أو مفاتيح webhook يتبع runbook المزود.
