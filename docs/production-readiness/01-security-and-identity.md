## الهدف

أن تمثّل كل جلسة هوية صحيحة ومسموحاً لها بالعمل، وأن تبقى ضوابط الدخول فعالة تحت السباق وانقطاع الخدمات، وأن تُلغى الأسرار المكشوفة دون فقدان بيانات مشفّرة.

تجميد الميزات الجديدة مستمر؛ أي إضافة هنا يجب أن تعالج حاجب أمن ضمن نطاق الإطلاق المعتمد في P00.

## المشكلة والأدلة

هذه مراجعة مصدر ووثائق بتاريخ الخطة، وليست اختبار اختراق أو إثباتاً لحالة الإنتاج الحيّة.

| البند | الدليل وحدوده |
|---|---|
| خلط رموز التسجيل والدخول | [JwtAuthGuard](../../back-end/src/auth/guards/jwt-auth.guard.ts) يتحقق من التوقيع ثم يستخدم `sub` دون تحقق صريح من نوعه أو غرض الرمز؛ [OptionalJwtGuard](../../back-end/src/auth/guards/optional-jwt.guard.ts) يحمل النمط نفسه. سلسلة تسريب `me` واردة في التقرير §6؛ يلزم إثبات محلي ببيانات اختبار. |
| تراجع عدّاد OTP عند الخطأ | [OtpService](../../back-end/src/otp/otp.service.ts) يحدّث `attempts` و`locked_until` داخل معاملة ثم يرمي استثناء؛ يلزم اختبار قاعدة حقيقية لإثبات بقاء الأثر المطلوب. لا نعمّم هذا على قفل كلمة المرور. |
| سباق التجديد وإبطال الجلسة | [AuthService](../../back-end/src/auth/auth.service.ts) يحتوي مسار قراءة ثم تحديث رمز التجديد، ومسارات تغيير كلمة المرور التي تحتاج مراجعة إبطال access tokens أيضاً. |
| تعطل Redis يرخّي الحماية | [محدد المعدل](../../back-end/src/common/guards/throttle.guard.ts) يسمح بالطلب عند عطل التخزين؛ وسياسة [إبطال الرموز](../../back-end/src/auth/token-revocation.service.ts) تحتاج اختبار فشل مستقل. |
| أسرار وُصفت بأنها مكشوفة | [قائمة الإطلاق القديمة](../go-live-checklist.md) والتقرير §6 يسجلان تعرض بيانات اعتماد؛ لا يوجد في هذه الخطة تأكيد حي بأن التدوير حصل أو لم يحصل. |
| مسار تدوير أحدث موجود | [SecretCryptoService](../../back-end/src/common/crypto/secret-crypto.service.ts) يقبل المفتاح السابق، و[SecretRotationService](../../back-end/src/integrations/secret-rotation.service.ts) يعيد تشفير التكاملات وحسابات شركات الشحن، بما فيها المحذوفة منطقياً. هذا لا يثبت تشغيله على الإنتاج. |
| مخاطر إضافية تحتاج إعادة إثبات | التقرير §6 وملحق الهوية يذكران redirect مفتوحاً، session fixation، MFA غير موجود وثغرات اعتماديات. تراجع النسخة الحالية قبل تصنيف كل بند؛ لا نعتمد أرقام الإصدارات أو نتائج `audit` التاريخية حكماً حالياً. |

المصدر الجامع: [تقرير الجاهزية](../investor-readiness-report-ar.md)، §5 و§6 وملحق المصادقة والهوية.

## الحل المعتمد

1. عقد واحد لرمز الوصول: هوية غير فارغة صحيحة الشكل، غرض موثّق، حمولة صلاحيات مضبوطة، وفصل رموز التسجيل والاستعادة عنه. تُحدَّد معاملة الرموز القديمة قبل النشر.
2. تطبق القاعدة في GraphQL وREST وSSE والمسارات ذات المصادقة الاختيارية؛ الرمز المرفوض لا يترك هوية جزئية في الطلب.
3. تثبيت أثر محاولات OTP الفاشلة قبل إرسال خطأ للعميل؛ تجديد الجلسة عملية ذرية تمنع إصدار عائلتين من الرمز نفسه.
4. إبطال الجلسات عند تغيير كلمة المرور أو تعليق الحساب أو سحب صلاحية، مع سياسة معلنة لتعطل Redis في العمليات الحساسة.
5. تدوير الأسرار على مراحل قابلة للتحقق؛ لا يكفي ضبط مفتاح تشفير جديد قبل تدوير `APP_SECRET`.

## النطاق والاستثناءات

- يشمل الدخول والتجديد والاستعادة وOTP وحماية كتابة cookies وredirect والأسرار واعتماديات المسارات المنشورة.
- يشمل قرار حماية حسابات الإدارة بعامل ثانٍ أو ضابط وصول مكافئ موثّق قبل العمليات المالية؛ لا يُغلق البند بوعد مستقبلي.
- تفاصيل ملكية المتاجر وصلاحيات الموارد في P02، وإثبات إرسال البريد وSMS وإعداد البيئة في P03، وشاشات الاستعادة في P09.
- لا تشمل المرحلة إعادة كتابة نظام الهوية أو إضافة تسجيل اجتماعي أو SSO تجاري.

## المهام بالترتيب

- [x] **P01-T01** — إنشاء حالات إعادة إنتاج محلية للرمز بلا `sub`، رمز التسجيل كـBearer، وOTP الخاطئ؛ تدوين المسارات المتأثرة والأثر دون بيانات حقيقية. عند وجود سطح منشور مكشوف، احتواؤه فوراً بتعطيل المسار المتأثر أو إصلاح مراجع.
- [x] **P01-T02** — توحيد التحقق من payload في جميع الحراس والمداخل؛ إضافة حماية داخل `me` وأي خدمة لا يجوز استدعاؤها بمعرّف مفقود؛ اختبار رفض الرمز قبل استعلام المستخدم.
- [x] **P01-T03** — إصلاح OTP بحيث تبقى المحاولة والقفل مسجّلين بعد الخطأ، ومنع إعادة استعمال الكود والتجاوز بطلبات متزامنة؛ الحفاظ على انتهاء الصلاحية وحدود الإرسال.
- [x] **P01-T04** — جعل استهلاك refresh token وإصدار البديل ذريين؛ توثيق سلوك تبويبين متزامنين، وإعادة الاستخدام المشبوهة، وlogout وتغيير كلمة المرور وتعليق الحساب.
- [x] **P01-T05** — توحيد التحقق من Origin قبل كتابة جلسة في التطبيقات الثلاثة؛ تقييد redirect بوجهات داخلية معروفة؛ اختبار الصيغ المشفّرة و`//host` وعدم تسريب token في URL.
- [x] **P01-T06** — تحديد سياسة عطل Redis لكل مسار حساس: OTP والدخول والطلبات وكتابة السلة والإبطال؛ تطبيق رفض منضبط أو حماية بديلة مثبتة مع تنبيه، دون سماح غير محدود صامت.
- [x] **P01-T07** — إعداد سجل أسماء الأسرار ومواقع استخدامها ومالكيها وتاريخ الإلغاء، دون القيم؛ تشمل قاعدة البيانات وRedis والتوقيع والذكاء الاصطناعي والبريد والتخزين وwebhooks والمراقبة حسب الجرد الفعلي.
- [x] **P01-T08** — تجربة تدوير التشفير على نسخة معزولة: حفظ نسخة احتياطية ومادة المفتاح القديم في مخزن أسرار، ضبط مفتاح جديد و`SECRETS_ENCRYPTION_KEY_PREVIOUS` بالقيمة القديمة المستخدمة فعلاً، ثم تشغيل مسار إعادة التشفير الحالي. يلزم حصر كل جدول مشفّر قبل البدء.
- [~] **P01-T09** — إثبات أن جميع الصفوف قابلة للفك وأن `failed=0`، وإعادة التشغيل بلا صفوف تحتاج تدويراً؛ اختبار قراءة التكاملات وحسابات الشحن بالمفتاح الجديد وحده. بعدها إزالة fallback السابق من الخدمة وتدوير `APP_SECRET` وإلغاء credentials عند مزوديها؛ تنسيق روابط الدخول وwebhooks المتأثرة. **محلي Docker `zaydak` مكتمل** ([سجل التدوير](p01-secret-rotation-log.md)). **إلغاء المزودين / تدوير إنتاج Render خارج نطاق جولة التطوير** (قيم مختلفة عن الإنتاج؛ ملك تشغيل). يبقى `[~]` حتى يغلق التشغيل الإنتاج.
- [x] **P01-T10** — إتمام مراجعة حماية الإدارة والجلسات وحساسية البريد لحالة الأحرف؛ حسم الحسابات المتعارضة قبل أي normalization. تشغيل تدقيق اعتماديات حالي لكل lockfile والتحقق من advisories الرسمية والإصلاحات الملائمة قبل الترقية.
- [x] **P01-T11** — تحديث توثيق auth وOTP والتكاملات وعقود API وقائمة go-live المتأثرة في تغييرات التنفيذ، وإرفاق نتائج الاختبارات وسجل التدوير المنقّح من الأسرار.

## المخرجات المطلوبة

- تغييرات أمنية محددة، مع اختبارات فشل ونجاح لكل مدخل متأثر.
- مصفوفة الجلسات: إصدار، تجديد، إبطال، خطأ، وتعطل خدمة خارجية.
- إجراء تدوير محدث يغطّي كل البيانات المشفّرة وسجل أسماء الأسرار الملغاة وتواريخها.
- قرار موثّق لحماية الإدارة والرموز القديمة، مرتبط بسجل القرارات في P00.

## سيناريوهات التحقق

| السيناريو | النتيجة المطلوبة |
|---|---|
| رمز تسجيل صحيح التوقيع يستدعي `me` | رفض دون قراءة أي مستخدم أو إرجاع بيانات شخصية. |
| JWT بلا `sub` أو بغرض خاطئ عبر REST وSSE وGraphQL | رفض متسق؛ المسار الاختياري يعامل المتصل كزائر دون هوية جزئية. |
| عدة OTP خاطئة ثم طلب جديد ثم الكود الصحيح | العدّاد محفوظ والقفل لا يزول بإصدار كود جديد؛ لا يصدر token أثناء القفل. |
| تبويبان يجدّدان الرمز نفسه في وقت واحد | نتيجة متوافقة مع سياسة السباق الموثقة؛ لا جلستان مستقلتان من استهلاك واحد. |
| تغيير كلمة المرور مع token قديم | الجلسة القديمة مرفوضة وفق زمن الإبطال المعتمد، بما فيها access token. |
| Redis غير متاح | مسارات حساسة لا تصبح بلا حماية؛ خطأ مفهوم وتنبيه قابل للرصد. |
| نقل مفتاح التشفير ثم حذف السابق | كل تكامل وحساب شحن ما زال يُقرأ؛ لا `DECRYPTION_FAILED` ولا fallback بيئي يخفي صفاً تالفاً. |
| طلب عابر للمواقع لكتابة الجلسة أو redirect خارجي | رفض كتابة الجلسة والوجهة الخارجية، مع استمرار الدخول المشروع. |

## شروط القبول

- [x] لا رمز من غرض آخر يتحول إلى جلسة مستخدم؛ نجاح الاختبارات على المداخل الثلاثة.
- [x] OTP والقفل والتجديد والإبطال مثبتة باختبارات قاعدة بيانات وسباق، لا mocks فقط.
- [ ] لا سر مكشوف في جرد المرحلة باقٍ صالحاً دون معالجة موثقة؛ لا قيم أسرار في أدلة الإغلاق.
- [x] كل الصفوف المشفّرة قابلة للقراءة بالمفتاح الجديد؛ النسخة الاحتياطية قابلة للاستعادة بإجراء واضح.
- [x] لا ثغرة حرجة قابلة للاستغلال في النطاق المنشور باقية من مراجعة الاعتماديات الحالية.
- [x] حماية الإدارة وقرار تعطل Redis منفذان، وتوثيق التنفيذ ونتائج التحقق مرفقان.

## الاعتماديات والقرارات المفتوحة

- P00 يحدد حسابات الاختبار والبيئة وصلاحيات التنفيذ؛ لا يؤجل ذلك احتواء تسريب مؤكد.
- P02 يستعمل عقد الهوية هنا ويملك صحة سحب الصلاحيات الفردية والجماعية.
- P03 يملك الوصول التشغيلي وإثبات البريد/SMS والنسخ الاحتياطي؛ يمكن تجربة التدوير معاً قبل إغلاقهما.
- يلزم تحديد مدة الجلسة وسياسة الرموز القديمة وحماية الإدارة ومدة الاحتفاظ الآمن بمفاتيح استعادة النسخ القديمة.

## التراجع والتعافي

- لا يُعاد نشر حارس معروف بأنه يسمح بتسريب؛ عند تعذر الإصلاح يوقف المدخل المتأثر مؤقتاً.
- عند فشل تدوير صف: إبقاء نافذة قراءة المفتاح السابق محدودة، معالجة الصف، وإعادة الاختبار قبل حذف المفتاح.
- استرجاع إصدار الخدمة وحده لا يعيد تشفير الصفوف إلى المفتاح القديم؛ يلزم إصدار يفهم المفتاح الجديد أو إجراء استعادة مختبر.
- لا تعاد credentials ملغاة إلى الخدمة؛ يستخدم سر جديد، وتبطل الجلسات عند الحاجة وتوثق نافذة الأثر.
