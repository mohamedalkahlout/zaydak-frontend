# P11 — الإطلاق والتشغيل بعده

| الحقل | القيمة |
|---|---|
| الحالة | لم تبدأ |
| المالك | مسؤول الإصدار + مسؤول التشغيل + صاحب المنتج |
| الاعتمادات | اجتياز P00–P10 على النسخة المرشحة؛ D01–D10 محسومة بقدر ما يخص الإصدار |
| الأولوية | بوابة فتح الإنتاج للعملاء |
| المخرج | إصدار منشور ومراقب، ودليل استمرارية وتشغيل وتسليم |

## الهدف

إطلاق النسخة التي اختُبرت فعليًا، بنطاق معلوم وحجم يمكن مراقبته، مع طريقة مجرّبة لإيقاف التدفق المتأثر واستعادة الخدمة دون فقد قيود مالية أو بيانات.

## المشكلة والأدلة

- [التقرير](../investor-readiness-report-ar.md) و[قائمة الإطلاق](../go-live-checklist.md) يسجلان إعدادات وتشغيلًا وتكاملات غير مثبتة، لذلك نجاح البناء محليًا لا يكفي.
- وجود خدمة مستضافة أو علامة نجاح في CI لا يثبت أن OTP يصل، أو أن العملية المالية تطابق المزوّد، أو أن النسخة الاحتياطية قابلة للاستعادة.
- [دليل التشغيل الخلفي](../../back-end/docs/12_runbook/README.md) و[دليل التاجر](../../apps/vendor/docs/12_runbook/README.md) أساس لتسليم التشغيل؛ نربط الإجراءات المختبرة بهما.

## الحل المعتمد

حزمة إصدار واحدة تربط الكود والترحيلات وإعدادات التشغيل وأدلة قبول كل مرحلة. ننفذ تجربة نشر وتراجع على بيئة مماثلة، ثم إطلاقًا تدريجيًا ومراقبة ضمن حدود D08. لا يتجاوز قرار تجاري حاجب أمن أو سلامة مال أو التزامًا ينطبق على النطاق.

## نطاق المرحلة

يشمل النشر، الترحيلات المعتمدة، اختبار الدخان، متابعة المدفوعات والإشعارات والمراقبة والدعم والاستجابة للحوادث. لا يدخل أي عمل ميزة جديدة أثناء نافذة الإصدار؛ الضروري يمر كإصلاح له تحقق جديد.

## خطوات التنفيذ

- [ ] **P11-T01:** جهز حزمة release candidate: SHA للنسخة، build artifacts، إصدارات الترحيلات، قائمة إعدادات بلا قيم سرية، وملخص الفروق عن النسخة السابقة.
- [ ] **P11-T02:** راجع أدلة P01–P10 وسجل الحاجبات والتغطية. أي شرط بلا دليل يبقى مفتوحًا. ثبت قائمة الاستثناءات المعتمدة فقط للقدرات التي أُخرجت بأمان من النطاق.
- [ ] **P11-T03:** أعد تجربة نشر كاملة على staging من حزمة الإصدار نفسها: ترحيل، تهيئة مرجعية آمنة، تشغيل API والعمال والواجهات، تحقق health/readiness ثم الرحلة التجارية.
- [ ] **P11-T04:** جرّب استعادة نسخة احتياطية في قاعدة منفصلة وسجل زمنها وفجوة البيانات الفعلية مقابل D08. اختبر فك إعدادات التكاملات المشفرة بعد الاستعادة دون إعادة أسرار مكشوفة للخدمة.
- [ ] **P11-T05:** جرّب التراجع عن التطبيق مع توافق المخطط، وتعطيل checkout أو تكامل بعينه، وإعادة معالجة أحداث اختبارية دون مضاعفة طلب أو قبض أو استرجاع.
- [ ] **P11-T06:** استكمل جاهزية الحسابات والنطاقات والشهادات والبريد وSMS والمزوّد المالي وحدود السعة والفوترة والتنبيهات، مع دليل اختبار لكل خدمة مفعلة.
- [ ] **P11-T07:** عيّن مناوبًا وبديلًا ومالك قرار الإيقاف، وقناة بلاغات دعم وزمن استجابة وحدود تنبيه. وثق التصعيد إلى المزوّدين ومسؤول المال.
- [ ] **P11-T08:** اتخذ قرار الإطلاق من قائمة البوابات أدناه، وسجل صاحب القرار والوقت ونطاق الدفعة الأولى. لا يبدأ التحويل العام قبل هذا السجل.
- [ ] **P11-T09:** نفذ النشر وفق ترتيب التوافق المتحقق في P03. شغّل اختبارات دخان سريعة على الإنتاج ببيانات وحسابات مخصصة؛ العملية المالية الحقيقية الصغيرة لها سقف ومسؤول وتسوية واسترجاع مسجلان.
- [ ] **P11-T10:** وسّع الوصول على دفعات ضمن حدود D08. راقب نسبة فشل تسجيل/دفع/طلب، تأخر webhooks والعمال، استهلاك الموارد والتكاليف وتطابق دفتر المال مع المزوّد.
- [ ] **P11-T11:** نفذ مراجعات تشغيل بعد 24 ساعة و72 ساعة و7 أيام كجدول أولي يعتمد في D10. قلة الزيارات لا تثبت السعة؛ اربط هذه المراجعات بنتائج حمل P10 وبحالات فعلية/اصطناعية معلومة.
- [ ] **P11-T12:** سلّم وثائق الدعم والحوادث والتسوية والاستعادة، وأغلق المرحلة بعد نافذة المراقبة المعتمدة ومعالجة حوادثها الحاجبة. سجّل المتبقي في TODO بمعرّفات الخطة.

## بوابات قرار الإطلاق

| البوابة | شرط النجاح | الدليل |
|---|---|---|
| الأمن والعزل | لا تسريب أو عبور متاجر أو أسرار مكشوفة صالحة للاستخدام | P01 وP02 |
| التشغيل | بيئة صحيحة، migrations وseed مرجعي قابلان للتكرار، restore مجرّب | P03 |
| اكتشاف الأعطال | خطأ اختباري يصل مع سياقه إلى تنبيه ومسؤول، وCI يمنع فشلًا مؤثرًا | P04 |
| التجارة | سعر ودفع ومخزون وضريبة وإلغاء واسترجاع متسقة | P05 |
| المال | دفع وعمولة وتسوية وصرف بلا تكرار أو مبلغ غير مفسر | P06 |
| الامتثال | حسم الانطباق وأدلة المتطلبات المعتمدة لكل تدفق | P07 |
| التكاملات | القنوات المفعّلة تعمل، القياس والحصص والتكلفة واختبارات الفشل مثبتة | P08 |
| الاستخدام والدعم | الرحلات الأساسية للتطبيقات الثلاثة قابلة للإتمام والمعالجة | P09 |
| السعة والتحقق | اختبارات E2E والتزامن والحمل على النسخة المرشحة اجتازت D08 | P10 |
| الاستجابة | مناوب وبديل وصلاحية إيقاف وتجربة rollback واستعادة | P11 |

## سيناريوهات التحقق

1. تاجر جديد → وصول تحقق فعلي → متجر بصلاحيات واستحقاقات وBalance صحيحة → منتج منشور → شراء → تسليم/إلغاء → تسوية، ثم فحص ما يراه العميل والتاجر والمشغّل.
2. قطع اتصال مزوّد أو إعادة webhook أو ضغط شراء آخر قطعة: لا يظهر نجاح كاذب ولا يتكرر الأثر المالي؛ يصل تنبيه مناسب.
3. خطأ واجهة متجر وخطأ API وخطأ عامل: يمكن ربطها بإصدار وطلب دون كشف رموز أو بيانات شخصية.
4. إيقاف checkout مؤقتًا يبقي القراءة والدعم والتسوية القائمة في حالة مفهومة؛ إعادة فتحه لا تعيد تنفيذ العمل المنتهي.
5. استرجاع نسخة تطبيق متوافقة ثم replay مضبوط لأحداث معلقة ينتج القيود نفسها مرة واحدة.

## المخرجات

- manifest إصدار وأدلة البوابات وقرار إطلاق مسجل.
- نتائج smoke واختبارات التراجع والاستعادة وحدود السعة والحمل.
- جدول مناوبة وروابط إجراءات الحوادث والتسويات والدعم.
- سجل مراجعات النافذة الأولى والعيوب اللاحقة وملاكها.

## شروط الاجتياز

- [ ] اجتازت البوابات جميعها، وصفر حاجب مفتوح ضمن نطاق الإصدار.
- [ ] النسخة المنشورة هي النسخة التي تحمل أدلة الاختبار والترحيل.
- [ ] اختبارات الإنتاج المحدودة لا تترك بيانات طلبات أو مبالغ مجهولة المعالجة.
- [ ] مرت نافذة المراقبة المعتمدة دون حادث حاجب غير محلول، وتمت مطابقة المال والتكلفة.
- [ ] سلّم التشغيل والدعم إلى ملاك مسمّين، وطريقة الإيقاف والاستعادة مجرّبة.

## التبعيات والقرارات

لا نغيّر السوق أو مسار الأموال أو نطاق الميزات أو أهداف السعة داخل يوم الإطلاق. إذا تغيرت، نحدد المراحل المتأثرة ونعيد أدلتها قبل فتح المسار المتغير. الموافقة هنا بوابة تنفيذ مستقبلية؛ إعداد الخطة لا يُعد نشرًا أو شراء خدمة أو إرسال رسائل.

## التراجع والاستجابة

نوقف التوسع أو checkout المتأثر فور إثبات عبور بيانات، فرق مالي غير مفسر، تكرار خصم أو فقد مخزون، أو تجاوز حدود D08. نوقف العامل المسبب عند اللزوم مع حفظ الطابور والدليل. rollback يعيد تطبيقًا متوافقًا؛ لا يعكس تحويلًا لدى المزوّد ولا يحذف قيودًا محاسبية. تُعالج الأموال بتعويض/تسوية مدققة، وتُختبر استعادة قاعدة البيانات في نسخة منفصلة قبل أي قرار استبدال. لا نعيد مفتاحًا مكشوفًا كخطة تراجع.
